# Prizma Calendar

Яркий календарь, работающий без сети. Одна веб-сборка на три платформы: браузер (PWA),
десктоп (Tauri) и мобильные (Capacitor).

События с повторами, задачи с дедлайнами, напоминания, подписки на внешние календари,
импорт и экспорт `.ics`, резервная копия. Данные лежат локально в IndexedDB; аккаунта и
сервера нет.

## Быстрый старт

```
npm install
npm run dev          # http://127.0.0.1:5173
```

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер |
| `npm run build` | Сборка в `dist/` вместе с service worker |
| `npm run preview` | Отдать собранное (на нём проверяется офлайн) |
| `npm test` | Тесты |
| `npm run typecheck` | Проверка типов |
| `npm run icons` | Перегенерировать иконки PWA |

## Про CORS, и почему обёртки — не украшение

Google, iCloud и Outlook дают секретную ссылку на ваш календарь. Прочитать её **из
браузера нельзя**: на этих хостах нет заголовка `Access-Control-Allow-Origin`, и запрос
отклоняется до того, как дойдёт до кода. Это не ошибка приложения и не чинится настройкой.

Поэтому:

- В вебе работают только ленты, которые сами разрешают чтение из браузера. Для остальных
  приложение показывает понятное объяснение и предлагает импортировать `.ics` файлом.
- В десктопной и мобильной обёртках запрос идёт из нативного слоя, где CORS не применяется,
  и ленты работают по ссылке.

Обе обёртки подменяют ровно две реализации — загрузчик лент и доставку уведомлений, — и
делают это через `src/platform.ts`. Ни один модуль ниже не знает, на какой он платформе.

## Десктоп (Tauri 2)

**Требуется:** Rust (`rustup`), на Windows дополнительно Visual Studio Build Tools с
компонентом «Разработка классических приложений на C++», на Linux — `webkit2gtk` и
`libayatana-appindicator`.

```
npm install -g @tauri-apps/cli   # или npx tauri
npm run desktop:dev
npm run desktop:build
```

Права перечислены в `src-tauri/capabilities/default.json` и намеренно узкие: сеть только для
четырёх хостов календарей, диалоги открытия и сохранения файла, уведомления. Ни файловой
системы целиком, ни запуска процессов, ни оболочки.

Чтобы подключить десктопные реализации, вызовите `initDesktop()` из
`src/platform.desktop.ts` перед монтированием приложения.

## Мобильные (Capacitor 7)

**Требуется:** для iOS — macOS с Xcode; для Android — Android Studio и JDK 21.

```
npx cap add ios        # один раз
npx cap add android    # один раз
npm run mobile:sync
npm run mobile:ios     # или mobile:android
```

Напоминания уходят системе через `@capacitor/local-notifications`. iOS держит не больше 64
отложенных уведомлений, поэтому `scheduleNatively` берёт 64 ближайших: потерять напоминание
на следующий месяц переживаемо, на завтра — нет.

Чтобы подключить мобильные реализации, вызовите `initMobile()` из `src/platform.mobile.ts`.

## Как устроено

```
spec/           Спеки: карта модулей, фундамент, по файлу на модуль
tasks/          План и список задач с журналом сделанного
src/lib/        Чистая логика без React — время, повторы, ICS, хранилище, поиск
src/store/      Стор zustand и селекторы
src/components/ Компоненты по видам
src/platform.ts Точка подмены для обёрток
test/           Тесты на src/lib (node:test, без браузера)
src-tauri/      Обёртка десктопа
```

Два решения, которые объясняют остальное:

**Время хранится как «настенное»** — `2026-11-22T09:30`, без смещения и без `Z`. «Каждый
понедельник в 09:00» должно оставаться 09:00 и после перевода часов; на абсолютных моментах
недельное правило уезжало бы на час дважды в год.

**Удаление — это tombstone, а не удаление.** Запись остаётся с отметкой `deletedAt`. Без
этого будущая синхронизация не отличит «удалено здесь» от «ещё не приходило сюда» и
воскресит удалённое.
