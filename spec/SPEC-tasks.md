# Spec: tasks — V1

Status: proposed · Module id: `tasks` · Depends on: `storage` · Наследует [SPEC.md](SPEC.md)

## Objective

Задачи с дедлайнами рядом с событиями: то, что нужно сделать, а не то, что занимает время.
Отдельная сущность, а не событие нулевой длины — у задачи есть состояние «выполнено»,
приоритет и она не исчезает, когда её срок прошёл.

## Requirements

**Модель.** `Task` в `types.ts` уже описан: `title`, `notes`, `due`, `done`, `completedAt`,
`priority` (0–3), `reminders`, `order`, плюс sync-метаданные. Логика — в `src/lib/tasks.ts`.

**Срок необязателен.** Задача без `due` живёт только в панели и в сетке не показывается.
Задача с `due` как датой (`2026-11-22`) показывается в строке «весь день» этого дня;
задача с `due` как датой-временем — в этой же строке, но с временем в подписи. Задача не
занимает место в сетке часов: у неё нет длительности.

**Просроченность.** Задача просрочена, когда `due < now` и `!done`. Это вычисляемое свойство,
а не поле: иначе его придётся пересчитывать по таймеру и оно разойдётся с реальностью.
Просроченные показываются в панели сверху отдельной группой.

**Выполнение.** `toggleDone(task)` переключает `done` и пишет/снимает `completedAt`.
Выполненные скрываются из сетки сразу, из панели — по настройке `showCompletedTasks`.

**Сортировка в панели:** просроченные → с сегодняшним сроком → остальные с сроком по возрастанию
→ без срока по `order`. Внутри равных — по `priority` убыванием, затем по `order`.

**Порядок вручную.** `order` — число с плавающей точкой; вставка между соседями даёт
среднее их `order`. Причина: перенумеровывать весь список при каждом перетаскивании — это
запись сотни записей в IndexedDB вместо одной.

**Задачи в сетке — по настройке.** Решение 2 в [SPEC.md](SPEC.md#resolved-decisions):
флаг включён по умолчанию, выключается в настройках.

## Success Criteria

1. Задача создаётся без `due` и видна в панели, но отсутствует в выборке дня.
2. Задача с `due` как датой попадает в выборку для этого дня и ни для какого другого.
3. Задача с `due` вчера и `done = false` помечена просроченной; та же задача с `done = true` — нет.
4. `toggleDone` ставит `completedAt`, повторный вызов снимает его в `null`.
5. Сортировка панели на наборе из просроченной, сегодняшней, будущей и бессрочной задач
   даёт именно этот порядок.
6. При равном сроке задача с `priority = 3` стоит выше задачи с `priority = 0`.
7. Вставка между двумя задачами меняет `order` только у перемещённой.
8. Выключенная настройка `showCompletedTasks` убирает выполненные из панели, но не удаляет их.

## Boundaries (delta)

- **Never:** превращать задачу в событие, чтобы показать её в сетке. Это разные сущности,
  и склейка сломает и повторы, и ICS-экспорт.

## Out of Scope

- Повторяющиеся задачи — V2; RRULE у задачи означает другую семантику («сделать снова»),
  и её стоит продумать отдельно.
- Подзадачи и вложенность — V2.
- Экспорт задач в `VTODO` — формат поддержан единицами клиентов; полный дамп эту роль закрывает.
