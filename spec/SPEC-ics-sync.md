# Spec: ics-sync — V1

Status: proposed · Module id: `ics-sync` · Depends on: `calendar-core` · Наследует [SPEC.md](SPEC.md)

## Objective

Связь с внешним миром через формат, который понимают все: iCalendar. Импорт и экспорт файла,
плюс подписка на ленту по ссылке — то, чем в V1 закрывается пункт «Google/Apple/Outlook»
(допущение 1 карты, решение 1 в [SPEC.md](SPEC.md#resolved-decisions)).

## Requirements

**Разбор.** `src/lib/ics.ts`, функция `parseIcs(text): { events, calendarName? }`.
Обязательно обрабатывает то, на чём ломаются наивные парсеры:

| Особенность формата | Требование |
|---|---|
| Складывание строк | Строка, начинающаяся с пробела или таба, — продолжение предыдущей; склеить до разбора |
| Переносы | `\r\n`, `\n` и `\r` — все три |
| Экранирование в тексте | `\n` → перевод строки, `\,` `\;` `\\` → символ |
| Параметры свойства | `DTSTART;TZID=Europe/Berlin:20261122T090000` — значение после первого `:`, не после первого `;` |
| `VALUE=DATE` | Событие на весь день; `DTEND` в ICS уже исключающий — не сдвигать повторно |
| Отсутствие `DTEND` | Взять `DURATION`, иначе: весь день → +1 день, со временем → длительность по умолчанию |
| `UTC` (`Z`) | Привести к локальному настенному времени |
| `TZID` | V1: читать как настенное время указанной зоны через `Intl`, не как UTC |
| Неизвестные свойства | Игнорировать, не падать |
| `VTODO`, `VALARM`, `VTIMEZONE` | Пропускать целиком, не ломая разбор остального |

Правило модуля: **битая строка пропускается, разбор продолжается.** Один сломанный `VEVENT`
в ленте из пятисот не должен лишать пользователя остальных 499. Число пропущенных возвращается
в результате и показывается в интерфейсе.

**Генерация.** `serializeIcs(events, calendars): string`. Складывание строк на 75 октетах,
обязательные `PRODID`, `VERSION:2.0`, `UID`, `DTSTAMP`. Повторы пишутся как `RRULE`, исключения
как `EXDATE`. Переносы `\r\n` — по букве RFC 5545.

**Импорт файла.** Выбор `.ics`, предпросмотр («найдено N событий, M пропущено»), выбор
календаря-назначения, затем запись. Дедупликация по `uid`: существующее событие обновляется,
а не дублируется.

**Подписка на ленту.** Календарь с `kind: 'ics-feed'` и `url`. Обновление: загрузить, разобрать,
сверить по `uid` — новые добавить, изменённые обновить, исчезнувшие удалить (tombstone).
Обновление по расписанию `refreshMinutes` (по умолчанию 60) и по кнопке. Ошибка загрузки
пишется в `lastSyncError` и показывается на календаре, но прошлые события остаются.

**События ленты — только чтение.** `readOnly` у календаря, правка в интерфейсе заблокирована.
Причина: правка будет затёрта следующим обновлением, и честнее не дать её сделать.

**CORS — известное ограничение.** Браузер не даст прочитать ленту Google или iCloud напрямую:
на этих хостах нет заголовка `Access-Control-Allow-Origin`. Следствия, и их надо отразить в
интерфейсе, а не обнаружить при тестировании:

- В вебе работают только ленты с разрешающим CORS; при ошибке показывается объяснение
  и предложение импортировать файлом.
- В `shell-desktop` и `shell-mobile` запрос идёт из нативного слоя, где CORS не применяется,
  и ленты работают. Это настоящая причина, по которой обёртки нужны, а не только «чтобы было приложение».
- Прокси в V1 не делаем: это сервер, то есть V2.

## Success Criteria

1. Файл со сложенной строкой (`SUMMARY` в 200 символов, разбитый на три) даёт одно событие
   с полным названием.
2. Файл с `\r\n`, с `\n` и с `\r` разбирается одинаково.
3. `SUMMARY:Встреча\, важная\nвторая строка` даёт запятую и настоящий перевод строки.
4. `DTSTART;TZID=Europe/Berlin:20261122T090000` разбирается в 09:00, а не в значение после `;`.
5. `DTSTART;VALUE=DATE:20261122` + `DTEND;VALUE=DATE:20261123` даёт событие на весь день
   длиной один день, а не два.
6. `VEVENT` без `DTEND`, но с `DURATION:PT90M` даёт событие длиной 90 минут.
7. Один сломанный `VEVENT` среди трёх даёт два события и счётчик пропущенных = 1.
8. `VTODO` и `VALARM` во входном файле не создают событий и не ломают разбор `VEVENT` после них.
9. `parseIcs(serializeIcs(events))` возвращает события, равные исходным по названию, времени,
   признаку «весь день» и правилу повтора.
10. Сгенерированный файл имеет строки не длиннее 75 октетов и переносы `\r\n`.
11. Повторный импорт того же файла не создаёт дублей (сверка по `uid`).
12. Повторное обновление ленты без изменений на сервере не меняет число событий.
13. Обновление ленты, из которой событие исчезло, ставит ему tombstone.
14. Ошибка загрузки ленты пишется в `lastSyncError` и не удаляет ранее загруженные события.
15. Экспортированный файл открывается в Google Calendar без ошибок (проверка руками).

## Boundaries (delta)

- **Always:** пропускать битую запись и продолжать; возвращать число пропущенных.
- **Ask first:** любой новый хост в запросах.
- **Never:** отправлять данные пользователя куда-либо; обмен только на чтение с URL,
  который ввёл пользователь.
- **Never:** разрешать правку события из ленты.

## Out of Scope

- Двусторонний обмен по OAuth с Google/Apple/Outlook — нужен сервер токенов и ревью приложения; V2.
- `CalDAV` (`REPORT`, `PUT`) — имеет смысл только после двустороннего обмена; V2.
- Прокси для лент без CORS — это сервер; V2. В обёртках платформ проблема снимается сама.
- `VTODO` при импорте — задачи из ICS не вытаскиваем, формат мало кто пишет.
