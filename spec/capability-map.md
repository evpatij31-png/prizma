# Capability Map: Prizma Calendar

Status: proposed — awaiting review

## Assumptions I'm making

Correct any of these now; otherwise the module specs are written against them.

1. **«Синхронизация с Google/Apple/Outlook» в V1 — это односторонняя подписка, а не двусторонний OAuth.**
   Чтение календарей по секретной ICS-ссылке (её даёт и Google, и iCloud, и Outlook) плюс импорт/экспорт `.ics`.
   Полноценный двусторонний обмен требует OAuth-клиента, сервера для обновления токенов и ревью приложения у
   Google и Apple — без аккаунтов разработчика и бэкенда это недостижимо. Уходит в V2, вместе с облаком.
2. **В V1 нет аккаунтов и сервера.** Данные лежат в IndexedDB на каждом устройстве, то есть устройства между
   собой пока не синхронизируются. Слой данных пишется так, чтобы облако добавлялось без миграции:
   tombstone вместо удаления, iCalendar UID, `updatedAt` как часы слияния, `etag` под валидатор сервера.
3. **Десктоп — Tauri, мобильные — Capacitor, обе обёртки поверх одной веб-сборки.** На этой машине нет
   ни Rust, ни Xcode/Android Studio, поэтому здесь получаются конфиги и инструкция сборки, но не бинарники.
   Собрать их сможешь ты у себя или CI.
4. **Интерфейс русский, неделя с понедельника, 24-часовое время**, всё остальное форматирование — через `Intl`
   по локали устройства.
5. **Напоминания в вебе — Web Notifications + Service Worker.** Пока приложение полностью закрыто, веб-уведомления
   негарантированы (особенно в iOS Safari). Надёжные напоминания приходят вместе с `shell-mobile`.
6. **Один часовой пояс — локальный на устройстве.** Время хранится как «настенное» (`2026-11-22T09:30`, без
   смещения), поэтому «каждый понедельник в 09:00» остаётся 09:00 и после перевода часов. Отдельный часовой
   пояс у события — V2.
7. **«Яркий и живой» = насыщенные градиенты, крупные цветные блоки событий, анимированные переходы**,
   тёмная тема по умолчанию и светлый вариант.

## Modules

| Module id | Responsibility | Depends on |
|---|---|---|
| `storage` | Хранилища IndexedDB, схема и миграции, tombstone-удаление, экспорт/импорт сырой базы | — |
| `calendar-core` | Модель события, разворачивание RRULE, запрос вхождений на интервал, раскладка пересечений | `storage` |
| `tasks` | Модель задачи: дедлайн, выполнение, приоритет, порядок | `storage` |
| `reminders` | Планирование напоминаний и локальные уведомления для событий и задач | `calendar-core`, `tasks` |
| `ics-sync` | Разбор и генерация ICS, импорт/экспорт файла, подписки на ленты и их обновление | `calendar-core` |
| `ui` | Оболочка приложения, виды месяц/неделя/день/список, редакторы, drag & resize, яркая тема | `calendar-core`, `tasks`, `reminders`, `ics-sync` |
| `shell-web` | PWA: манифест, service worker, офлайн, установка | `ui` |
| `shell-desktop` | Обёртка Tauri для Windows/macOS/Linux | `shell-web` |
| `shell-mobile` | Обёртка Capacitor для iOS/Android, мост к нативным уведомлениям | `shell-web`, `reminders` |

Build order: `storage` → `calendar-core`, `tasks` → `reminders`, `ics-sync` → `ui` → `shell-web` → `shell-desktop`, `shell-mobile`

## V1 boundary

**В V1 входит:** `storage`, `calendar-core`, `tasks`, `reminders`, `ics-sync`, `ui`, `shell-web`,
плюс конфиги `shell-desktop` и `shell-mobile` с инструкцией сборки.

## Out of Scope (Deferred to V2)

Одна строка на идею: что и почему отложено.

- **Облако и аккаунты** — нужен бэкенд и модель доступа; слой данных к этому готов, но это отдельный цикл.
- **Двусторонний Google/Apple/Outlook по OAuth** — нужны аккаунты разработчика, сервер токенов и ревью приложения.
- **CalDAV-запись** — имеет смысл только после облака и двустороннего обмена.
- **Совместные календари, приглашения участников, свободно/занято** — требуют сервера и аккаунтов.
- **Часовой пояс у отдельного события и перелёты** — заметная сложность в UI и в разворачивании повторов.
- **Собранные бинарники десктопа и сборки в сторах** — нужны Rust/Xcode/Android Studio и подписи.
- **BYWEEKNO / BYYEARDAY в повторах** — в реальных календарях практически не встречаются.
- **Поиск по всей истории с индексом** — в V1 достаточно поиска по загруженному интервалу.
